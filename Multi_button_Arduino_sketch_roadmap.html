RRCI Firmware V2 Development Roadmap

This document outlines the proposed architecture and development plan for RRCI Firmware Version 2.

The primary goal is to preserve full backward compatibility with existing Aleko single-button installations while allowing support for future motor controllers that require dedicated Open, Close, and Stop inputs.

Design Goals

  • Maintain 100% compatibility with existing RRCI V1 installations.
  • Support multiple controller architectures.
  • Require no ASCOM driver changes.
  • Preserve existing serial command protocol.
  • Improve relay abstraction and maintainability.
  • Support future commercial and industrial roof motors.

Supported Controller Types

Mode Description Inputs
Mode 1 Aleko Single Button Open / Stop / Close cycle via one input
Mode 2 Open / Close Controller Dedicated Open and Close inputs
Mode 3 Open / Close / Stop Controller Dedicated Open, Close and Stop inputs

Controller Type Enumeration

enum ControllerType
{
    ALEKO_SINGLE_BUTTON = 1,
    OPEN_CLOSE = 2,
    OPEN_CLOSE_STOP = 3
};

Relay Architecture

Firmware V2 separates roof actions from physical relay hardware.

Relay Assignments

#define RELAY_OPEN      7
#define RELAY_CLOSE     6
#define RELAY_STOP      5
#define RELAY_SPARE     4

Abstraction Layer

PulseOpenRelay();
PulseCloseRelay();
PulseStopRelay();

Roof control code should never manipulate relay pins directly. All relay access should occur through these functions.

Roof Action Layer

OpenRoof();
CloseRoof();
AbortRoof();

These functions become the only entry points for roof motion.

Behavior changes automatically based on configured controller type.

ASCOM Driver Compatibility

No changes are required to the existing ASCOM driver.

The driver continues sending: 

open
close
abort
status
ping

Firmware V2 translates those commands internally.

Command Mapping

Action Mode 1 Mode 2 Mode 3
Open Roof Pulse OPEN relay Pulse OPEN relay Pulse OPEN relay
Close Roof Pulse OPEN relay Pulse CLOSE relay Pulse CLOSE relay
Abort Roof Pulse OPEN relay No action Pulse STOP relay

Runtime Configuration Commands

Future firmware versions may allow runtime configuration.

Command Description
setmode:1 Select Aleko Single Button Mode
setmode:2 Select Open/Close Mode
setmode:3 Select Open/Close/Stop Mode

EEPROM Storage

Controller type should be stored in EEPROM. 

EEPROM Address 0

ControllerType

On startup: 

controllerType =
    (ControllerType)EEPROM.read(0);

Invalid values automatically revert to: 

ALEKO_SINGLE_BUTTON

Status Reporting Enhancements

Current status response: 

STATE:OPEN;SAFE;MOVING#

Proposed V2 response: 

STATE:OPEN;
SAFE;
MODE:1;
MOVING#

This allows diagnostics software to determine the active controller type.

Future Enhancements

  • Web-based configuration page
  • EEPROM-backed settings storage
  • Remote firmware update support
  • Network telemetry
  • Relay activity diagnostics
  • Motion history logging
  • Controller auto-detection

Backward Compatibility Commitment

Important:

Default firmware behavior shall remain: 

ALEKO_SINGLE_BUTTON

Existing observatories must continue operating exactly as they do today after upgrading to Firmware V2.

No ASCOM driver modifications should be required.
